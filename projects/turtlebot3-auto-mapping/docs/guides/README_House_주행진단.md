# 미탐색 영역으로 유도하고 망설임 로그 수집하기

## 적용

자동 탐색기만 Ctrl+C로 종료합니다. 최신 `house_nav2_frontier.py`와 `tools/diagnostics/diagnose_house_motion.py`를 우분투 `~/ros2_practice_ws`에 복사합니다. 진단 파일은 우분투에서 `~/ros2_practice_ws/diagnose_house_motion.py` 위치로 둡니다. 배포 ZIP을 사용하면 이 이름으로 들어 있습니다. colcon build는 필요하지 않습니다. 기존 0.10m/s 프로필의 Gazebo·Cartographer·Nav2는 유지할 수 있습니다.

자동 탐색 터미널:

```bash
source ~/ros2_practice_ws/house_env_cyclone.bash
export ROS_DOMAIN_ID=30
python3 ~/ros2_practice_ws/house_nav2_frontier.py --ros-args -p use_sim_time:=true
```

## 미탐색 경계로 접근하는 방식

현재 기본 동작은 관심 지점까지 자동 선택하는 방식입니다. 미탐색 경계의 미관측 셀 하나를 관심 위치로 고르고, 그 앞의 알려진 빈 공간에 이동 목표 하나를 둡니다. Publish Point를 직접 클릭할 필요가 없습니다. 도착·실패·취소의 결과를 확인한 뒤 다음 목표를 고릅니다. 내부 후보 계산은 여러 대안을 비교하지만 대기 이동 목표와 활성 액션은 각각 하나로 제한합니다.

이전에는 후보 주변 360도 전체의 미탐색 면적으로 평가했습니다. 현재는 선택한 경계 방향의 120도 범위 예상 관측 면적을 우선 평가하고, 경계에서 멀리 머무는 후보에 추가 비용을 줍니다. 가까운 후보와 경계에 더 접근하는 후보를 함께 평가하여 가까운 후보만 최종 비교에 남는 현상도 줄였습니다.

라이다는 360도를 관측하므로, 도착 후 경계를 향한 별도 회전을 강요하지 않습니다. Nav2가 확인한 경로의 마지막 진행 방향으로 도착 자세를 맞추되, 그 자세의 몸체가 빈 공간에 들어갈 때만 변경합니다. 출발점 복귀에서는 원래 출발 방향을 유지합니다.

미탐색 셀을 빈 공간으로 바꾸거나 충돌 검사를 끄지 않습니다. 지도에서 확인된 안전한 위치까지 접근 → 새 스캔과 지도 갱신 → 다음 목표를 선택합니다. 가상 광선의 예상 관측 면적은 아직 보이지 않는 장애물을 모르는 추정치입니다.

## 빨간 원처럼 특정 영역을 우선 탐색하기

이 절차는 자동 선택을 수동으로 우선 지정하고 싶을 때만 사용합니다.

1. RViz Fixed Frame을 `map`으로 둡니다.
2. **Publish Point** 도구를 선택하고 탐색시키고 싶은 미탐색 영역 안을 한 번 클릭합니다.
3. MarkerArray `/house_frontier/markers`에서 분홍 점과 `EXPLORE HERE`가 표시됩니다.
4. 기존 목표가 있으면 취소 완료 후, 클릭 위치에 가까운 미탐색 경계를 우선하는 후보를 재계산합니다.

이 기능은 Nav2 Goal을 미탐색 좌표 안에 직접 보내는 기능이 아닙니다. 그 영역으로 접근할 수 있는 알려진 빈 공간의 안전한 목표를 선택합니다. 벽으로 막힌 영역이나 아직 연결 경로가 없는 곳까지 통과를 보장하지 않습니다. 특정 영역을 선택하지 않아도 자동 경계 탐색은 계속 수행합니다.

## 경로는 하나만 표시하기

RViz의 Path 표시를 하나만 남기고 Topic을 `/house_frontier/path`, Buffer Length를 `1`로 지정합니다. 기존 `/plan`, 로컬 경로 등을 표시하는 다른 Path 항목은 체크 해제합니다. MarkerArray `/house_frontier/markers`는 현재 관심 위치와 선택된 목표만 표시합니다. 여러 파란 후보점은 기본 표시에서 제외했습니다.

전용 경로 토픽은 현재 목표와 끝점이 일치하는 Nav2 최신 경로만 보여줍니다. 이전 경로는 새 목표 시작·취소·실패·도착 때 빈 메시지로 교체합니다. 재계획에 따라 같은 한 경로의 모양은 바뀔 수 있지만 여러 목표를 동시에 주행시키지 않습니다. 다른 자동 탐색기나 RViz 수동 Nav2 Goal을 동시에 실행하지 마세요.

## 일반 탐색 뒤 막힌 면 확인

기본 `inspect_blocked=true`입니다. 미탐색 경계가 안정적으로 사라져도 바로 복귀하지 않고, 알려진 장애물 중 접근 가능한 빈 공간과 접한 막힌 면을 약 1m 구간별로 골라 앞쪽 관측 위치를 차례로 방문합니다. 문으로 보이는 구역만 대상으로 삼지 않습니다. 일반 탐색 후보가 20초 이상 안정적으로 없는 경우에도 접근 가능한 막힌 면을 재관측하여 새 지도가 생기는지 확인합니다.

관측 목표는 벽 좌표 자체가 아니라 몸체가 들어가는 빈 공간입니다. 새 경계가 생기면 일반 탐색으로 돌아갑니다. 이미 재관측을 시도한 면 주변은 같은 실행에서 반복 방문을 줄입니다. 도달 실패한 면은 `inspection_history`에 success=false로 기록합니다. 안전한 관측 후보조차 없거나 미탐색 경계가 계속 남으면 완료로 판정하지 않습니다. 연결된 경계가 안정적으로 사라지고 막힌 면 확인 시도까지 끝나면, 실패한 면의 미확인 개수를 로그로 알린 뒤 출발점으로 복귀합니다. 벽 뒤의 폐쇄 공간을 관측했다고 간주하지 않습니다.

전체 자동 선택으로 돌아가려면:

```bash
ros2 topic pub --once /house_frontier/clear_preference std_msgs/msg/Bool '{data: true}'
```

Publish Point는 `/clicked_point`를 발행합니다. 자동 탐색은 이 토픽을 관심 영역 지정으로 사용하므로 수동 Nav2 Goal과 구분하세요. 관심 위치는 odom 기준으로 보관해 이후 map 보정 때 재투영합니다.

## 60초 주행 진단

별도 터미널에서 자동 탐색을 실행한 상태로 관측합니다. 실제 시간 60초로 끝나므로 Gazebo가 일시정지돼도 진단 명령 자체가 영원히 기다리지 않습니다.

```bash
source ~/ros2_practice_ws/house_env_cyclone.bash
export ROS_DOMAIN_ID=30
python3 ~/ros2_practice_ws/diagnose_house_motion.py --seconds 60
```

5초 간격으로 간단한 상태를 출력합니다. 주행 명령·파라미터 변경·목표 전송은 하지 않습니다. 마지막에 출력되는 아래 형식의 파일을 보내면 됩니다.

```text
~/ros2_practice_ws/diagnostics/motion_<실행시각>.json
```

파일에는 1초 간격의 명령·실제 속도·시간 상태·탐색 액션 상태와 최근 Nav2 경고/오류, 마지막 전체 탐색 상태, 최근 경로·로컬 원본 비용지도·몸체 윤곽, cmd_vel 발행 노드 목록이 담깁니다. 외부 상태 파일이 오래됐거나 아직 없으면 그 사실도 기록합니다. 비용지도·경로는 각각의 마지막 수신 시각을 포함하며 완전히 같은 순간의 동기 스냅샷은 아닙니다.

| 화면 분류 | 확인할 내용 |
|---|---|
| 시간 갱신 중단 | Gazebo 재생·clock·통신 |
| 라이다 수신/시각 불일치 | 센서 공백 또는 시간 동기 |
| 경로 응답 대기 | planner 준비·계산·경로 실패 |
| 회전/10초 이상 작은 위치 변화 | 방향 정렬인지 복구 동작인지 Nav2 로그와 대조 |
| 목표 진행 중 0 명령 | 제어기의 궤적 거부·정지 상태 등 확인 |
| 명령 대비 작은 실제 움직임 | 접촉·물리·명령 경합 등 확인 |
| 활성 목표 없음 | 후보 부족·완료·준비 상태 확인 |

분류 문구는 원인 확정이 아닙니다. 예를 들어 회전은 정상 방향 정렬일 수 있으며, 명령과 오도메트리는 서로 다른 시점에 수신될 수 있습니다.

## 탐색기 자체의 사건 로그

기존 `house_nav2_frontier_state.json`은 최신 상태 한 장을 5초 간격으로 저장합니다. 현재 버전은 목표 선택부터 결과까지의 사건도 다음 경로에 추가 기록합니다.

```text
~/ros2_practice_ws/diagnostics/frontier_events_<실행번호>.jsonl
```

시작 시 실제 경로를 출력합니다. 사건 종류는 준비 상태 변경, 후보 선택, 경로 요청, 목표 접수 거절, 액션 결과, Nav2 피드백, 도착 방향 변경, 관심 영역 지정, 일시정지입니다. 실행 중인 로그를 바로 보려면:

```bash
tail -f "$(ls -t ~/ros2_practice_ws/diagnostics/frontier_events_*.jsonl | head -n 1)"
```

진단 결과와 같은 실행의 사건 로그를 같이 보내면 어떤 후보에서 거절·취소·회전이 반복됐는지 확인하기 쉽습니다. 이 로그는 생성 자료이므로 Git 기본 추적에서 제외합니다.

## 검증 범위

현재 유지 검사 93개를 통과했습니다. 자동 관심 위치와 안전 목표 분리, 단일 대기 목표, 취소 완료 전 새 주행 금지, 경로 삭제, 막힌 면의 안전 목표와 반복 방지, 경계 방향 정보량, 진단 분류와 JSON 형식 등을 검사했습니다. 실제 Ubuntu ROS 통신·Gazebo 주행은 이 Windows 환경에서 실행하지 않았습니다.

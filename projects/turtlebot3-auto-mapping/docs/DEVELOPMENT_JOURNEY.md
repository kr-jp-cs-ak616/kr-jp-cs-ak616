# 개발 과정: 증거로 가설을 좁히기

이 문서는 대화 중 제공된 실행 로그·측정 결과와 보존된 분석 자료를 바탕으로 작성했습니다. 완료된 결과와 아직 검증되지 않은 구현을 구분합니다. 초기 방식의 중복 실행 스크립트는 정리하고, 문제·판단·설계 전환을 이 기록으로 남깁니다.

## 1. 기둥 월드에서 자동 탐색과 지도 저장

처음에는 explore_lite의 프런티어 탐색을 Cartographer·Nav2와 연결했습니다. 초기 충돌, 노드 누락, 비용지도 미발행을 점검한 뒤 사용자는 충돌 없이 탐색한 결과와 `No frontiers found` 종료 로그를 제공했습니다. 이어 map_saver가 125×116, 해상도 0.05m 지도를 저장했고 `.pgm`, `.yaml` 생성이 확인됐습니다.

이 결과는 기둥 월드의 한 실행에 대한 성공 기록입니다. House 전체 탐색이나 반복 성공률을 입증하는 자료는 아닙니다. 지도 원본·영상은 현재 Windows 폴더에 없으므로 포트폴리오에 완성 지도 이미지가 있는 것처럼 표시하지 않습니다.

## 2. 멈춤을 모두 충돌로 해석하지 않기

House에서는 목표 취소, progress checker 실패, 시뮬레이션 시간 중단, 과거 TF 조회 오류, 기하 충돌 거부가 번갈아 나타났습니다. 원인을 구분하지 않고 속도나 허용 오차를 바꾸는 대신 입력·노드·시간·액션 상태를 나누어 관측하도록 발전시켰습니다.

| 현상 | 확인한 증거 | 판단 |
|---|---|---|
| 목표 취소 | explore_node의 No frontiers found 직후 취소 | 제어기 충돌 실패와 구분 |
| TF 변환 실패 | 과거 윤곽 시각과 현재 TF 버퍼 간 수백 초 차이 | 실제 Collision Ahead와 구분 필요 |
| 시뮬레이션 시간 중단 | Gazebo 일시정지와 clock 갱신 중단 | 반복 주행 대신 정지 |
| 지도 왜곡 | 회전 시 벽 중첩, 외부 TF 시각 정상인 관측도 존재 | 단순 RViz 축 표시 문제로 단정하지 않음 |

## 3. TF 시각 고정 문제의 원인 분리

20초 관측 자료에서 clock·scan·odom·TF·비용지도는 갱신됐지만 published_footprint는 126.043초에 고정돼 있었습니다. DDS 변경 후에도 재발했고, 설치 버전은 tf2/tf2_ros 0.25.23이었습니다. 공식 결함 보고와 변경 이력을 대조해 잠금 교착 수정이 포함된 0.25.24 업데이트를 검토했습니다.

사용자는 업데이트 뒤 윤곽 시각이 계속 갱신되고 회전도 수행됐다고 확인했습니다. 프로세스 역추적은 수집하지 않았으므로 모든 교착 경로를 직접 증명했다고 표현하지 않습니다.

## 4. 바퀴 오차 가설을 측정으로 검증

SDF에서 형상 축간 거리는 0.288m, 구동 설정은 0.287m, 바퀴 반경은 0.033m였습니다. 약 0.35%의 차이만으로 큰 지도 왜곡을 설명하지 않았습니다.

첫 수동 측정에서는 유효 축간 거리 약 0.206m와 큰 잔차가 나왔지만, 사용자가 접촉·헛돎 구간이 있었다고 확인해 적용하지 않았습니다. 이후 접촉 없는 직진·좌우 회전 측정 결과는 다음과 같습니다.

현재 프로필은 지름 0.066m를 유지하고 구동 축간 거리만 모델 형상 0.288m로 맞춥니다. WORLD odom을 엔코더 모드로 바꾸어 오차가 사라졌다고 주장하지 않습니다.

## 5. 벽 추종에서 정보 획득 기반 Nav2 목표로 전환

직접 벽 추종은 열린 공간의 식탁 다리, 입구 우편함, 같은 방 재방문에서 막혔습니다. 이후 미탐색 경계와 단거리 경로를 직접 추종했지만, 미탐색 셀을 포함한 시작 몸체 검사와 모서리 경로 추종에서 추가 실패가 나타났습니다.

현재는 역할을 나눴습니다. 탐색기는 관측 목표를 고르고 Nav2가 주행·장애물 회피를 수행합니다. 목표를 미탐색 셀 안에 직접 두지 않고, 그 경계를 볼 수 있는 알려진 빈 공간에 둡니다. 가시성 검사와 예상 관측 면적/이동 거리 평가를 추가하고, 경로가 유효한 후보만 액션으로 전송합니다. RViz 표시는 경계·후보·전송 목표를 구분합니다.

기존 벽 추종·문 후보·방 단위 관리 코드는 최종 실행 경로에서 제거했습니다. 해당 접근이 모든 환경에서 잘못됐다는 뜻은 아니며, 이번 프로젝트에서는 주행 제어를 Nav2로 통합하는 방향을 선택했습니다.

## 6. 과도한 원형 충돌 모델 수정

사용자 실행값에서 robot_radius=0.28, footprint=[]가 확인됐습니다. 이는 지름 0.56m 원으로 검사하는 설정입니다. 로봇 중심과 지도 장애물 거리가 약 0.29m였던 관측은 여유 부족을 의심할 근거였지만 로컬 궤적 거부의 전체 원인을 확정하는 자료는 아니었습니다.

표준 몸체·바퀴를 포함하는 사각 윤곽을 도입하고, DWB도 BaseObstacle 대신 ObstacleFootprint로 전체 윤곽을 검사하도록 수정했습니다. 이 변경이 실제 정지를 해결했는지는 새 세션 검증이 필요합니다. 반경을 무조건 줄여 충돌 검사를 통과시키는 방식과 구분합니다.

## 7. 현재 상태와 다음 검증

- 0.10m/s·0.20rad/s 운용 프로필과 실제 수정 모델을 스폰하는 launch 파일을 준비했습니다.
- 순수 로직·설정·기구학·비교 설정·주행 진단 검사 93개를 유지합니다.
- House 전체 탐색 성공, 지도 품질, 출발점 복귀의 실제 완료를 확인해야 합니다.
- 반복 횟수, 성공률, 이동 거리, 탐색 소요 시간, 지도 비교 오차는 아직 산출하지 않았습니다.
- 지도·라이다·odom·TF·cmd_vel을 같은 실행에서 기록하고, 변경 전후를 동일 시작 위치·조건으로 비교하는 것이 다음 단계입니다.

진행 중인 결과를 완성된 자율주행 성능으로 포장하지 않는 것이 이 기록의 원칙입니다.

## 8. 좁은 출발 위치에서 후보 생성과 주행 윤곽 일치

Nav2를 사각 윤곽으로 바꾼 뒤에도 탐색기의 후보 검사는 0.30m 원을 요구하고 있었습니다. 제어기가 통과할 수 있는 복도에서도 탐색기가 목표를 만들지 못할 수 있는 구조적 불일치를 수정했습니다. 후보 생성에도 표준 Waffle Pi 사각 윤곽과 0.01m 여유를 적용하고 지도 셀과 회전된 몸체의 겹침을 검사합니다. 현재 방향·접근 방향·경계 방향 중 몸체가 들어가는 자세를 선택합니다. 몸체가 들어갈 수 없는 통로와 미탐색 셀로 몸체가 넘어가는 후보는 계속 거부합니다.

지도 해상도 0.025m, 폭 0.40m 복도에서 원형 검사는 실패하지만 사각 몸체 목표는 생성되는 회귀 검사를 추가했습니다. 폭 0.25m 통로·지도 회전·몸체 아래 장애물과 미탐색도 검사합니다. 실제 House 새 출발 주행은 추가 검증이 필요합니다.

## 9. 경계 쪽 진행 유도와 망설임 관측

주변 전체 미탐색 면적만으로 후보를 비교하면 선택한 경계와 다른 방향의 공간이 점수에 영향을 줄 수 있었습니다. 경계 방향의 예상 정보량과 경계까지의 접근 거리를 반영하고, 경계 가까운 후보도 최종 비교에 포함하도록 수정했습니다. 사용자가 Publish Point로 관심 영역을 지정하면 그 주변 경계를 우선하되 Nav2 경로·몸체 검사를 유지합니다.

탐색 사건 JSONL과 읽기 전용 주행 진단 도구를 추가하여 목표 선택·액션 결과·속도 명령·오도메트리·Nav2 경고·원본 비용지도를 함께 기록합니다. 이 관측으로 실제 회전·정지 원인을 확인할 수 있게 했으며, 분류만으로 충돌이나 기구학 문제를 확정하지 않습니다.

## 10. 자동 관심 위치·단일 경로·막힘 재관측

Publish Point를 수동으로 클릭하지 않아도 미탐색 관심 위치를 하나 자동 선택하도록 했습니다. 내부 비교 후보와 실제 대기 목표를 구분하고, 대기 목표 하나·활성 액션 하나만 유지합니다. 취소의 최종 결과를 받기 전에는 새 주행을 보내지 않으며, 전용 표시 경로도 기존 경로를 교체하거나 비워 하나로 유지합니다.

일반 탐색이 끝나도 알려진 막힌 면을 구간별로 골라 접근 가능한 앞쪽을 재관측합니다. 같은 실행에서 확인 시도한 구간은 반복 방문을 줄입니다. 벽을 통과하는 목표는 만들지 않으며, 도달 실패나 관측 후보 부족을 완전 탐색으로 포장하지 않습니다. 순수 로직 검사 외에 실제 House 장기 주행 검증은 남아 있습니다.

## 11. 소형 창고로 실험 환경 확장

House 비교 환경을 보존하면서 AWS 소형 창고의 ros2 분기 자산을 연결하는 준비 코드와 별도 런처를 추가했습니다. 모델 파일의 model:// 경로뿐 아니라 file://models/... 메시 경로도 해석할 수 있도록 Gazebo 모델·미디어 검색 경로를 명시했습니다. 월드 경로를 gzserver에 직접 전달하고, 검증한 Waffle Pi 구동 모델을 명시적으로 스폰합니다.

월드·모델·메시 참조·원본 보존 검사와 원본 커밋/월드 해시 기록을 추가했습니다. 창고에서는 기존 자동 관심 위치·단일 목표·막힌 면 재관측 로직을 그대로 시험할 예정입니다. 실제 다운로드·Gazebo 스폰·지도 품질·탐색과 복귀 결과는 아직 확인하지 않았습니다.


소형 창고 상단 관찰을 위해 원본 RoofB 모델만 제외한 별도 월드를 생성하도록 변경했습니다. 원본 자산과 벽·선반·조명은 보존하며, 실행 manifest에 원본·파생 월드 해시와 제외 모델을 기록합니다. 지붕 제거와 원본 보존 검사를 추가했습니다.


VM 부하 대응 옵션 `--vm-lite`를 추가했습니다. 원본 구조 배치를 유지하되 소품을 제외하고 그림자를 끄며 1ms 적분 간격에서 500Hz/0.5배 실시간 목표로 실행합니다. 기본 GUI를 끄며, 실제 VM 성능과 주행 검증은 미완료입니다.


AWS 경량 모드에서도 VM 사용이 어려워, 사용자의 맵 변경 허용에 따라 8×6m 단순 창고를 추가했습니다. 외부 메시·텍스처 없는 정적 상자 13개로 벽·선반·적재실을 구성하고 Gazebo GUI를 기본으로 켭니다. XML·출발 여유·1.2m 통로 구조를 검사했으며, 전체 검사 98개가 통과했습니다. VM 렌더링·주행은 아직 확인하지 않았습니다.


지도 표현 단계에 반복 관측 장애물/빈 공간 경계 추출과 제한 오차 RDP 직선 근사를 추가했습니다. 기존 지도·Nav2 입력을 유지하고 RViz LINE_LIST와 JSON/SVG만 생성합니다. 지도 고정 요구는 매핑 완료 후 저장 지도·AMCL의 map→odom 보정 절차로 대응합니다. 문 단절·미탐색 제외·좌표 변환 등 검사 후 전체 106개 통과, 실제 ROS 표시는 아직 확인하지 않았습니다.


2026-10-23: 사용자 화면에서 직선 Marker 동작을 확인했으나 원본 SLAM 변형이 재발했습니다. 직선 표시를 지도 보정으로 오해하지 않도록 현재 상태를 미해결로 기록하고, 문제 보존→새 매핑→정상 지도 저장→AMCL 주행의 모드를 통합 실행 안내에 분리했습니다. VM 재부팅이 모드 전환에 필요하지 않다는 점과 종료/유지 노드를 명시했습니다. 사용자 화면은 docs/evidence에 보존하며, 실제 VM 지도·bag은 아직 가져오지 않았습니다.
